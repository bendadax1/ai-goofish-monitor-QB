# r5 本地手动验收指南

> 历史指南：下文路径、指纹和“当前”均指 2026-09-24 的 r5，不是最新候选。`1.1.0.0-beta` 基于 r10 的状态见 [beta 版本说明](RELEASE_1.1.0.0-beta.md)；无需打包的当前开发验收见 [Launcher 开发指南](LAUNCHER_DEVELOPMENT.md)。勿照抄旧包路径作为新版制品身份。

更新：2026-09-24。本文只用于准备当前 r5 候选包的本机手测，不构成完整 P1 或公开发行放行。完整状态见[便携版验收状态](PORTABLE_ACCEPTANCE_STATUS.md)。

## 当前唯一候选包

- 解压目录：`launcher/dist/portable-acceptance-frozen-20260924-p1-r5/`
- ZIP：`launcher/dist/portable-acceptance-frozen-20260924-p1-r5.zip`
- ZIP SHA-256：`9f01503a2570f4b121143646979461ec83fcd5a6c1e7871567434e6ee605b91d`
- 清单 `current.json` 标记 `release_status: preview-integration`。这是集成验收预览候选，不是公开发布包；r1–r4 的执行步骤均为历史，不适用于 r5。

先校验 ZIP 指纹，再把 ZIP **全部内容**解压到一个全新、可写、独立的目录。r5–r10 历史候选的 EXE 位于包根；r11 的 Launcher EXE 位于 `launcher/`；r15 新候选可从包根 `AiGoofish.exe` 启动，并有 `uninstall.exe`。这些历史包均以各自清单和说明为准。不要只复制 EXE，不要从压缩包预览中直接运行，也不要把文件覆盖到旧实例或带有 `data` 的目录中。

在 PowerShell 中可核对 ZIP：

```powershell
Get-FileHash -Algorithm SHA256 .\launcher\dist\portable-acceptance-frozen-20260924-p1-r5.zip
```

结果必须与上面的 SHA-256 完全一致；不一致就停止手测并记录来源和文件，不要运行该包。

## 第一阶段：仅模拟模式验收原生界面

从全新解压目录打开 PowerShell，运行：

```powershell
.\AiGoofish.Launcher.App.exe --simulation
```

确认窗口标题或模式标记显示“模拟测试”/“本地运行控制演练”，并且组件和状态带模拟标识。`--simulation` 使用模拟控制器，不读取 `current.json`，不启动内置 PostgreSQL、Python 或业务 Web，也不触碰便携实例数据；可以用它检查原生窗口交互。

逐项手测并记录结果：

- [ ] 窗口原生显示正常：无空白、错位或裁切；拖动、最大化/还原和关闭行为符合界面提示。
- [ ] 选择窗口所在显示器及 Windows 缩放比例，目视检查布局；至少记录显示器分辨率和缩放比例。100%、125%、150%、200% 等档位按手边环境测试，不可把未测档位记为通过。
- [ ] 用键盘 Tab/Shift+Tab、Enter、Esc 导航当前可操作控件，焦点清楚可见，控件可用；记录无法到达或无反馈的控件。
- [ ] 运行模拟开始、取消（仅在界面提示允许时）、停止交互；确认状态反馈和日志变化合理，且均标有模拟状态。
- [ ] 检查系统托盘图标、菜单、隐藏后恢复窗口和安全退出行为；区分真实 Windows 托盘交互与模拟服务状态。若托盘不可见，记下 Windows 版本、缩放比例和操作步骤。
- [ ] 缩放窗口并检查长日志/内容区域；记录滚动、裁切、冻结或窗口无法恢复等现象。
- [ ] 关闭模拟 Launcher，确认进程退出；不需要为此清理或删除任何文件。

若启动时没有显示明确模拟标记，或出现 PostgreSQL/Python/真实服务进程，立即停止操作，记为失败并按下方规则保留现场。

## 第二阶段：可选的真实空实例启动

只有在你明确要测真实组件启动时才做这一阶段。真实模式会初始化或启动包内 PostgreSQL、Python 和业务 Web，并在新实例数据根写入状态。它不是模拟测试。

开始前必须同时满足：

- 使用另一个全新、普通用户可写的解压目录；该目录不得覆盖旧程序或已有 `data`。
- 实例只含新初始化的空库和合成验收数据；不得复用、复制或指向任何真实业务数据、旧 PGDATA、配置、密钥、登录态或备份。
- 读取界面显示/配置的 PostgreSQL 与 Web 端口，确认均可绑定且不属于其他进程；“没有监听者”不等于端口可用，Windows 系统排除端口也可能阻止绑定。若端口不可用、归属不明或 UI 状态不明确，停止，不让 Launcher 接管服务，也不要修改系统排除范围。
- 只由测试者主动双击最外层 `AiGoofish.Launcher.App.exe` 进入真实模式。不要附加 `--simulation`，也不要点击登录或账号配对。

真实模式仅观察空实例首次初始化、组件状态和正常停止；不要登录真实闲鱼账号，不要建立或运行抓取任务，不要调用付费 AI，不要配置或触发通知。任何一步若提示将使用既有数据、账号或外部服务，取消并记录。

## 失败现场保留

出现启动、初始化、停止或界面失败时，保留完整解压目录及其生成的 `data`、日志、锁、实例标记和密钥文件；不要再次启动、覆盖、移动、改名或清理现场，也不要手动删除 `postmaster.pid`、实例目录或任何密钥。

在解压目录的**父目录**新建带唯一后缀的 `DO_NOT_DELETE_FAILURE_YYYYMMDD-<编号>.txt` 标记，不覆盖已有文件；记录失败时间、测试阶段（模拟/真实）、包路径、操作步骤、脱敏后的错误摘要、Windows 版本、显示器分辨率/缩放比例，以及已知的端口占用情况。标记放在父目录，避免改变包内文件清单。必要时附窗口截图，先遮盖可能出现的用户名、路径或秘密值；不要记录密钥、Cookie、完整连接串或原始敏感日志。待有人核对状态和用途后再决定后续处理；本指南不授权删除失败现场。

## 自动证据与手测边界

r5 已有自动证据：发行扫描覆盖 8,077 个 payload 条目且无 findings；ZIP 成员、CRC、大小和哈希校验通过，包输入及控制输入前后指纹一致；实际包的 Host→PG 配置 CAS 和业务备份/恢复 E2E 均通过。冻结源码的 Docker 合成回归也已通过，原有容器及卷保持不变。

这些证据不表示原生窗口已经验收。Headless 测试不能代替本指南的窗口、Explorer 托盘、DPI 和键盘目视检查；干净 Windows x64 无开发工具环境、跨 Windows 用户/SID 的恢复、实际原生 UI 仍缺手测证据。请勿把模拟模式结果记为真实 PG/Python 启停通过，也勿将 r5 标为公开发行通过。
