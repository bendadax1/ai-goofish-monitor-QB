# Windows 便携版与 Launcher 落地规划

> 文档版本：0.8 · 建立日期：2026-09-12 · 更新日期：2026-09-24
> 状态：P1 已形成多项实现及隔离验收证据，包含旧 r2 包 Host→PG 空实例双周期、r1 真实 Host→PG 备份恢复、Docker 隔离 Compose 本机烟测、Headless Launcher/恢复 UI 与托盘生命周期；当前源码仍有未验收变更，尚未冻结重建最终 ZIP。干净 Windows、原生 DPI/Explorer 托盘、最终包备份恢复与 Docker 冻结后复跑仍是放行门槛；保留现行 MIT。
> 用途：本仓库便携发行与启动器的决策基线。后续任务先阅读本文及根目录 AGENTS.md、REPOSITORY_HYGIENE.md，不凭聊天记忆重新选路线。

## 1. 目标、决策与边界

目标体验：用户下载完整 ZIP，解压到可写目录，双击启动器，即可启动本地 PostgreSQL 和现有 Web 应用；不要求用户安装 Python、Git、数据库、依赖或拉取源码。平台登录、验证码、AI API 参数仍由用户完成。“离线可安装启动”不等于抓取与 AI 服务可离线运行。

### 1.2 首版不做

- 新增 SQLite 适配器、删除现有 JSON 后端、重写 PostgreSQL 业务层。
- 用户端源码管理、任意 pip 安装、插件市场、环境包管理器、模型下载中心。
- 默认注册 Windows 服务、开机自启、管理员运行或自动添加防火墙规则。
- 将远程 PostgreSQL 配置作为普通用户必经步骤。既有服务器部署方式保持，不由便携启动器接管外部数据库。
- 全量桌面化 Web 界面、默认提供 LAN 共享或公网访问。
- 把此次打包任务扩展成完整业务产品重构。

### 1.3 项目定位与双发行路线

用户已明确：本项目是闲鱼监控与 AI 推荐系统。此前误放的内容生产定位及其审核、成品、上传工作流已移除，不属于本项目需求。工作目录示例采用仓库名 `ai-goofish-monitor-QB`，`Launcher.exe` 仅为通用入口示例；沿用现有品牌资源，最终展示名可在发布前确认，不阻塞实现。

核心范围：监控抓取、条件筛选、AI / 贝叶斯分析、结果存储展示、通知推送。启动、迁移、升级、恢复不得擅自改变任务状态、用户隔离或通知策略；健康检查不触发真实抓取、付费 AI 或通知。

Windows 便携包与 Docker 是同一业务后端的两种发行方式。`Dockerfile`、`docker-compose.yaml`、`docker-compose.server.yaml` 已存在，用户确认保留这条打包路线；本轮仅检查文件存在和结构，未重新构建或验证容器运行。Launcher 只负责 Windows，不塞进 Docker；共享路径改造、配置优先级、schema 迁移必须验证 Docker 回归。容器通过挂载与环境变量管理路径，不能改成依赖 Windows 盘符或 Launcher。两种部署不直接共用正在写入的 PGDATA，也不宣称跨系统复制 PGDATA 可迁移。

| 证据位置（仓库相对路径） | 当前事实 | 便携化工作 |
| --- | --- | --- |
| `start_web_server.bat` | 检查系统 Python、创建 venv、安装依赖并启动 | 保留开发用途，另建发行启动入口 |

| `src/storage/migration.py` | 已有文件到 PG 的迁移范围及排除清单 | 扩展为可预览、可校验的导入流程，不承诺全量无损 |
| `src/web/main.py:lifespan`、`/health` | 启动可加载调度；health 仅基本存活响应 | 新增维护启动模式与受保护的就绪/身份检查 |
| `login.py`、`src/scraper.py` | 当前优先尝试系统 Edge | 便携模式优先使用随包验证的浏览器组合 |
| `src/web/settings_manager.py` 的 AI 配置读写 | PG 模式使用当前用户默认 API 配置；已有密钥设置状态及字段合并 | 复用后端服务，补配置 revision、权限、字段级更新和生效状态契约 |
| `src/web/ai_manager.py`、`src/web/ai_health.py` | 已有缓存健康快照、主动文本/视觉测试、检测时间与延迟 | 读取与真实测试分离；Launcher 不按现有默认参数同时触发全部探测 |
| `src/ai_handler.py`、`src/storage/models.py` 等本轮检查范围 | 未发现完整持久化调用量、Token、费用统计链路 | 用量采集是新增待办；健康快照不能冒充用量报表 |

### 3.4 视觉参数（建议值，不是用户已确认像素稿）

- 初始窗口约 1120×760 DIP，最小约 920×640 DIP；根据可用工作区收缩，验证 1366×768 和 100% / 125% / 150% / 200% 缩放。
- 浅灰底、白色卡片、深色正文、蓝色主按钮；控制台为深色视口。优先浅色，完整深色主题后置。
- 侧栏约 96–120 DIP；正文 14–16 DIP；圆角 8–12 DIP；间距采用 8 的倍数。横幅约 140–180 DIP 高，不抢占启动状态空间。
- 中文系统字体优先，不在线拉取字体；图标保持同一线性风格，采用可再分发素材或自有资源。
- 正文对比度至少 4.5:1；状态同时有文字和图标，不只用颜色；按钮目标约 44 DIP 或以上。
- 不以动画装饰制造假进度；键盘可操作，焦点清楚，尊重减少动态效果偏好。窗口变窄时公告转折叠/下移，不出现整页横向滚动。

### 3.6 控制台和窗口关闭

- 控制台顶部始终显示总体状态、运行时长、组件筛选、生成诊断包、启动/打开界面、停止服务。
- 采用只读日志视口；“清空显示”只清内存视图，不删除磁盘日志。暂停滚动不停止采集。
- 日志条目显示时间、级别、组件；有条数/内存上限，增量渲染，不能无限吃内存或使 UI 卡死。
- 普通入口叫“停止服务”，不直接照搬参考图的“终止进程”。强制终止仅为诊断高级操作，说明风险并二次确认。
- 关闭浏览器不停止服务。关闭 Launcher 首次询问后台运行或退出，可记住选择；进入托盘必须有可发现的打开/退出入口。
- 若用户选择退出：先停止新任务，等待任务安全结束，停后端，再安全停本应用数据库。UI 持续显示进度，不能先消失再留下未知后台进程。

### 3.7 产品分层：基础控制台，而非第二套业务系统

0.2 根据用户新方向，把 Launcher 从“启动管理窗口”扩展为“基础配置与运行概览”。这里的 API 首先指应用正在使用的 AI 服务连接、可用性和调用摘要，不是开放任意 HTTP 请求的开发者调试台。通知/抓取等外部接口首期仅显示后端已有的脱敏状态及详细入口。

| 能力 | Launcher 负责 | Web 系统负责 |
| --- | --- | --- |
| 运行控制 | 本实例启动、停止、重启确认、维护状态 | 具体任务的执行策略与业务规则 |
| 基础系统配置 | 启动行为、本机服务端口、目录状态；应用内可编辑字段经权限检查 | 权限、用户组、调度规则、复杂网络和数据库管理 |
| AI 基础连接 | 当前用户默认连接的 Base URL、模型名、密钥替换、配置完整性和手动测试 | 多配置管理、模型路由、提示词、视觉参数、重试/超时/Token 策略 |
| 系统状态 | 组件、磁盘、本应用资源、任务总量摘要、最近故障 | 任务明细、平台账号、结果、业务报表 |
| API 调用概况 | 当前用户在选定时间窗内的调用、失败、延迟、Token 摘要（按实现阶段开放） | 按任务/模型/日期细查、重试记录、高级分析 |
| 通知与平台账号 | “已配置/待登录/最近错误”等已有可信摘要，点击进入对应页面 | 渠道密钥、Webhook 内容、Cookie、账号登录与账号池策略 |

首页最多保留四组摘要：服务状态、资源状态、API 概况、待处理提醒；保留参考图的侧栏和蓝色主按钮，压缩横幅或公告而不是堆满卡片。API 详情用侧面详情区/页内展开，不增加一串顶层导航。尚无数据能力时不展示假数字。

### 3.8 配置字段、存储归属与生效方式

| 配置项 | Launcher 操作边界 | 唯一权威来源 | 生效规则（目标契约） |
| --- | --- | --- | --- |
| 自动打开管理页、最小化/退出偏好、显示设置 | 可编辑，不需业务后端 | `data/launcher/` 本地偏好 | 保存后即时或下次打开窗口，字段旁说明 |
| 打开 Launcher 后是否自动启动服务 | 可编辑，默认关闭，用户已接受 | 本地偏好 | 下次启动；不等同于 Windows 开机自启 |
| Web 本机端口 | 自动/固定模式；新实例默认自动、旧配置保持固定；运行中保存模式不重启，固定端口只暂存 | 编排层实例配置，revision/intent 事务保护 | 全停后启动时自动模式优先复用原端口、冲突时选择新端口，身份/Ready 成功才更新地址；固定模式经确认应用并支持失败回退。2026-09-27 实现及验收边界见 PORTABLE_PORT_FIXES_20260927.md |
| PostgreSQL 端口 | 首版只读或受控故障修复，不作为普通表单 | 编排层实例配置 | 必须核验集群停止及连接一致性 |
| 数据/日志/备份目录 | 查看、打开；不支持边运行边迁移 | 统一路径模块 | 位置迁移走独立向导，不靠改一个文本框 |
| 当前用户 Base URL、模型名称 | 在线登录且有 AI 配置权限后编辑 | PG 中该用户默认 API 配置，经后端服务读写 | 新请求/新任务使用新配置；老工作进程需返回“待任务重启”状态 |
| 当前用户 API Key | 仅“已设置/未设置”、替换与明确移除；不回显原密钥 | 同上，按既有加密方案评审补强 | 与连接配置一起提交，失效对应检测缓存 |
| 代理、TLS、重试、并发、输出上限 | 首版仅显示必要脱敏摘要与“高级设置”跳转 | Web 后端相应配置服务 | 由高级页面解释生效和影响范围 |
| LAN 访问、远程数据库、日志清理额度 | 首版不在基础表单启用 | 既有部署/后续专门方案 | 不暗中改防火墙、数据库部署或删除策略 |

Basic 设置分“系统运行”“AI 连接”两块；Launcher 自身偏好留在“启动器设置”，不要在两处重复相同字段。API Key 输入为空默认保持不变，移除需独立动作和确认；绝不把星号掩码回写成真实密钥。

同一份业务配置可有 Launcher 精简视图和 Web 完整视图，但必须调用同一后端校验/保存服务。Launcher 不直连数据库 CRUD，也不保存一份业务配置后启动时覆盖 PG。已有 `.env`、进程环境及 PG 配置优先级要显式梳理；界面显示当前配置来源和用户归属，不能只看文件是否存在。

保存流程：本地格式校验 → 服务端权限/字段/版本校验 → 字段级提交 → 返回已保存 revision 与实际生效范围 → 更新界面。提交前后区分“未保存”“保存中”“已保存且生效”“已保存待重启”“保存失败”。错误紧邻字段，并有键盘可定位的摘要；不只闪一个提示后消失。此交互采用 UI/UX 技能匹配的字段验证与错误定位建议。

并发编辑必须有 `config_revision` / ETag 等乐观并发机制。Web 先改过时，Launcher 不静默覆盖，要求刷新并核对冲突；只提交用户修改的允许字段，保留高级参数。写请求超时先按操作 ID/revision 查结果，不盲目重试。切页有未保存修改时提示，服务断开不能假报保存成功。

### 3.9 未启动、未登录、维护中的能力

| 状态 | 可以做 | 必须限制 |
| --- | --- | --- |
| 后端未启动 | 改 Launcher 偏好、检查端口/路径/组件、看本实例启动日志、启动服务 | 不读写 PG 中业务配置，不发 AI 请求；显示“启动并登录后配置” |
| 后端已启动、用户未登录 | 看本机组件与资源状态；进入受保护登录/首次引导 | 不展示用户模型/用量/任务摘要，不自动当管理员 |
| 已登录 | 按当前用户权限读取/编辑基础配置，主动测试，查看其调用摘要 | 不因持有本机启动权限获得其他用户业务数据 |
| 维护/迁移/更新中 | 看维护状态和本地诊断 | 禁止业务配置写入与主动外部测试，避免与迁移竞争 |
| 后端断开/会话过期 | 本机组件仍可用，解释状态；引导重新连接/认证 | 隐藏私有缓存；不把旧缓存当实时状态，不离线排队密钥写入 |

首次运行先启动本地服务并完成管理员创建/认证，再在 Launcher 引导配置 API；配置失败不妨碍用户进入 Web 排查。服务启动不以外部 AI 可用为前置条件。密钥未保存时仅在当前表单内存短暂保留，取消/退出清除，不生成明文草稿。

Launcher 的本机控制通道与业务用户会话分开：前者只管理实例，后者复用 Web 的认证和权限规则。可采用受保护的一次性配对/登录授权后发放短期、可撤销会话；具体方案 P0 确认。不得把永久令牌、密码塞入 URL，也不复制浏览器 Cookie 文件。切换账号立即清除上一个账号的卡片、测试结果和缓存；管理员跨用户汇总首版不开放。

### 3.10 系统状态：来源清楚、过期可见

| 状态组 | 建议展示 | 数据来源与限制 |
| --- | --- | --- |
| 核心服务 | PG/后端运行或故障、启动时间、实例版本、维护状态 | 编排层归属核验与就绪响应；浏览器“组件就绪”不等于有浏览器进程运行 |
| 本机资源 | 数据盘可用容量、本应用进程树内存、可选本应用 CPU | 本地采样，注明范围，不假装是全机或跨机器指标；CPU 可后置 |
| 任务摘要 | 当前用户运行/等待/失败数量、最近完成时间 | 后端已有状态聚合；缺队列定义时不虚构排队数 |
| API 配置 | 当前用户/来源、模型、密钥是否设置、最近检测与耗时 | 脱敏配置 + 已有健康快照；配置完整不等于服务可用 |
| 提醒 | 空间不足、服务故障、API 待配置、最近调用错误、可更新 | 有来源和时间，严重程度排序、同类合并，点击具体处理入口 |

每个快照携带 `observed_at`、有效期、实例/用户范围和数据来源。统一使用“正常、异常、未配置、尚未检测、数据过期、服务未启动、无权限”等状态；未知不显示 0 或绿色正常。上次 API 检测成功必须标注时间，配置 revision 改变后结果立即失效。

建议前台状态按 3–5 秒轻量采样，API 用量按 30–60 秒读聚合缓存，最小化后降频；具体数值需实测。采样只读本地/后端，不轮询外部模型服务。失败指数退避且有上限，同一刷新不重叠；提供最后更新时间与手动刷新。后端不可用时 UI 不受阻塞。

### 3.11 API 操作：保存、检查、真实测试必须分开

1. “保存配置”：不触发外部调用，只校验并持久化。
2. “检查配置”：仅验证必填项、URL/模型格式与密钥设置状态；不得称作连通成功。
3. “发送测试请求”：用户主动触发，先说明目标服务、模型、测试类型和可能费用；提交前展示本次是已保存配置还是未保存草稿。

默认只计划一次轻量文本请求、限制输出与超时，并显式关闭 SDK/业务隐式重试；否则必须在确认中说明最大尝试次数。现有统一检测默认可能执行多种探测，适配时不能直接沿用；视觉能力测试留在高级页面。未保存配置的测试结果不得覆盖已保存配置的健康缓存。

测试由后端执行统一网络策略，Launcher 不再独立接一套 SDK。UI 防重复点击，服务端以请求 ID 去重并限频；HTTP 超时/用户取消并不证明供应商未处理或未计费，标记结果未知，不自动再次发送。手动重试再次确认。测试只发固定非敏感内容，不取真实商品/用户数据。

更改 Base URL 的主机/端口/协议意味着密钥发送目标改变：停止复用旧密钥，要求确认目标并重新绑定凭据。仅允许明确支持的协议；默认 HTTPS，确需本机 HTTP 模型服务走明确例外。防范重定向携带认证信息到其他主机和借测试访问不应访问的内网/元数据地址，校验使用统一后端网络规则；凭据不得放 URL 查询串。

结果显示成功/认证失败/模型不可用/限流/超时/网络问题等脱敏分类，附测试时间和请求耗时。点击“详细配置”进入 Web 的对应页面；目标页面不存在就降级到已验证设置页，不构造猜测路由。跳转不带密钥/令牌，不把打开页面当成已登录或已保存。

### 3.12 API 用量口径与实现阶段

此处是新增遥测规划，不代表仓库已有计费系统；首期聚焦 AI，不声称统计所有外部 HTTP 调用。

| 指标 | 目标定义 | 缺失/失败时 |
| --- | --- | --- |
| 调用次数 | 区分业务逻辑请求数与实际出站尝试数，重试算额外尝试；测试单列 | 没有采集器显示“暂未采集”，不能显示 0 |
| 成功/失败 | 记录终态和错误分类；正在执行、取消、结果未知独立计数 | 不把未知当失败或成功；成功率注明分母为已知成功+失败的尝试 |
| 延迟 | 按明确口径记录一次完整尝试的端到端时间；最近一次/平均值注明样本窗 | 无样本显示“—”；不把单次连通测试延迟当全天业务平均值 |
| Token | 供应商返回的输入/输出及可用明细，与模型/配置 revision 关联 | 未返回 usage 为未知，显示覆盖率，不按字符数冒充精确 Token |
| 费用 | 后续有明确价格来源/版本、币种和 Token 分类时才做估算 | 明示“估算，不是账单”；缺价格/usage 不显示零费用，不跨币种直接相加 |
| 账户余额 | 首版不做 | 不推算余额，不把本应用用量当供应商全账户用量 |

“今日”使用明确的应用时区，建议默认跟随本机并显示时区；事件以 UTC 存储，指定半开时间窗，跨日/DST 变化测试。详情可选最近 24 小时，不能把滚动窗口与自然日混称。UI 说明只覆盖本实例开始采集后的数据，测试是否计入由明确筛选控制，默认与业务分开。

采集位置在实际执行 API 的后端/工作进程公共调用层，不由 Launcher 进程计数。事件至少包含唯一 attempt ID、逻辑 request ID、用户/配置 ID、模型、配置 revision、用途（业务/测试）、开始/结束时间、状态、延迟、usage 可用性。写入幂等，聚合去重，启动器重启不清零；禁止存提示词、图片、完整响应、密钥或完整敏感 URL。

遥测写入异常需记录并提示采集不完整，不因此重复调用供应商。必要缓冲有容量和保留期限，事件/聚合表也需要限额、索引和保留策略，不变成无限日志仓库；具体期限在采集实施前确认。按用户权限聚合，精简摘要不能泄露其他账户用量或错误内容。

实施切分：P1 先做基础连接配置、手动测试、缓存健康状态和系统状态；完整统计归入“用量增强”阶段，排在 P2 安全升级恢复之后，再加持久化次数/成功失败/耗时及可获取 Token，数据链路验收后才亮出数字。费用估算、趋势图、余额、多供应商高级管理后置，不阻塞便携版交付。用户已接受此优先级，不再作为待确认项。

## 4. 发行结构与数据边界

以下为目标布局，不是当前仓库结构；名字可在技术确认时调整，职责边界不可混淆。

```text
ai-goofish-monitor-QB/
├─ Launcher.exe                   稳定启动入口（通用示例名）
├─ launcher/                      启动器资源及自包含依赖
├─ updater/                       独立更新执行器
├─ current.json                   当前已提交组件组合，不含密钥
├─ app/<app-version>/             Python 业务代码、static、templates、默认资源
├─ runtime/<runtime-id>/          固定 Python 与已安装依赖
├─ browsers/<browser-id>/         与 Playwright 匹配的 Chromium
├─ postgres/<engine-id>/          PostgreSQL 二进制、备份恢复工具
├─ data/
│  ├─ launcher/                   偏好、实例标识、运行/更新状态记录
│  ├─ config/                     应用配置、凭据及加密密钥（受保护）
│  ├─ postgres/<cluster-id>/      数据库集群，独立于程序版本
│  ├─ state/                      平台登录态及其他持久文件
│  ├─ assets/                     用户文件、提示词等（实际映射盘点后确定）
│  ├─ results/                    数据库以外的业务文件
│  └─ logs/                       分组件轮转日志
├─ backups/                       数据库、配置、密钥和文件资产的受保护备份
└─ .tmp/updates/<transaction-id>/  可重建更新暂存，受容量规则约束
```

- `APP_DIR`、`DATA_DIR`、`CACHE_DIR` 等统一解析；程序位置不依赖工作目录、PATH 或固定盘符。所有外部调用传明确参数，避免拼接 Shell 命令。
- 默认整目录便携；停止所有相关进程后才能移动。首版优先支持本地 NTFS 可写路径，中文/空格路径纳入测试；网络盘、同步盘、U 盘不承诺支持。
- 首版不做运行中的数据根迁移。外置素材目录后置；一旦支持，备份界面必须列出未包含的外部资产。
- 配置和数据库路径由同一解析模块提供；`.env` 的自动发现及 override 行为要适配，不能意外读到开发目录或父目录配置。
- `runtime-id` 绑定 Python 与完整依赖锁；依赖变化可先整体更换此组件，不强制首版再拆一层依赖包。
- 当前系统仍可能把部分资料存文件；使用 PG 不代表一切都已入库，备份不能只有数据库。
- ZIP 只含干净程序和默认模板；禁止包含本机 `.env`、数据库、Cookie、API 密钥、任务记录、开发 venv、日志或真实配置。
- 便携版不承诺隐藏 Python 源码或防复制；目标是免部署，不是源码加密。

## 5. 技术边界与选型门槛

### 5.1 架构职责

| 组件 | 责任 | 禁止 |
| --- | --- | --- |
| Launcher UI | 即时显示窗口、状态订阅、基础配置表单、用户操作、只读诊断 | 依赖业务后端/PG 就绪才能绘制；直写业务数据库或绕过业务权限 |
| 启动编排层 | 单实例、路径解析、PG 生命周期、应用启停、状态机 | 按进程名批量杀 Python/PostgreSQL |
| 业务后端 | 现有功能、事务、认证、维护门控、身份/就绪检查；统一配置校验、API 测试与状态/用量聚合 | UI 进度自行假定为业务就绪；未认证返回私有摘要 |
| 更新器 | 验签、暂存、停机协调、备份、迁移、版本切换与恢复 | 从公告或任意 URL 执行脚本 |

编排层与 UI 解耦，日志和状态事件可测试。可采用结构化本地管道/受保护 IPC，具体协议待选型；不要只靠匹配日志里的“成功”二字判断状态。

建议状态事件字段：`run_id`、`component`、`phase`、`state`、`message`、`elapsed_ms`、`error_code`、`retryable`、`safe_to_cancel`。不得包含凭据、Cookie 或原始业务内容。

Launcher 接入契约需明确：能力/协议版本、字段允许清单、当前用户权限、脱敏读取、配置 revision、字段级保存、实际生效范围、主动测试的去重 ID、摘要数据时间窗与新鲜度。可复用 `/api/settings/ai`、`/api/settings/health/ai` 等现有业务服务，但不可假设现有接口已满足全部契约。尤其现有字段合并不等于已有并发冲突保护；实现前补相应测试。Launcher 与后端版本不兼容时保留本机启停，禁用不支持的业务编辑并提示升级。

### 5.2 已确认技术路线（原型进展见 10.2）

采用 C# / Avalonia UI + 自包含 .NET 发布，以独立窗口承载 Launcher；Python 后端保持当前脚本结构。Avalonia 提供多桌面平台基础，核心框架采用 MIT 许可，但各系统版本支持级别不同；框架能力不等于本产品已验证多平台。[平台支持](https://docs.avaloniaui.net/docs/supported-platforms)、[核心框架许可](https://github.com/AvaloniaUI/Avalonia/blob/main/licence.md)

自包含发布随应用携带 .NET 运行时，不要求用户另装；采用目录式自包含发行即可，不追求把全部后端压进一个 EXE。发布体积和系统兼容性须实测。[Microsoft 发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/)

选择理由：目前没有已有 WPF 实现需要保留；提前降低未来 UI 迁移成本，但不扩大当前发行范围。UI 与 Python/PG 故障域分离，通过受保护接口复用业务服务；使用 XAML 和明确视图状态组织表单、状态卡片、日志。优先基础控件，不引入大型商业控件库；固定经过验证的框架版本，不追随每次大版本升级。

用户已确认 Avalonia 路线，不再把 WPF 与 Avalonia 反复列为平行待选项。具体 .NET/Avalonia 稳定版本、Windows 最低构建、PG/Python 组合和依赖清单经兼容验证后记录，安装按仓库规则执行。发现阻断时提出证据和替代方案再改路线；不自行换 Electron/WebView/Python GUI。Docker 沿用 Python 服务，不携带桌面运行时。

P0 原型验证：小首页、配置表单、持续日志及模拟后台启动任务；分别测量窗口首屏、可交互时间、空闲内存/CPU、长日志滚动和 DPI 表现。PG/Python/抓取浏览器的启动与资源单独记录；原型测试前不承诺启动秒数、体积或比其他框架更省内存。数据库等待不能阻塞 UI，日志需有界缓存与批量更新。

### 5.3 跨平台铺垫范围（当前只实现 Windows）

| 边界 | 当前实现 | 不提前做 |
| --- | --- | --- |
| UI 与视图状态 | Avalonia 页面、配置/状态绑定 | macOS/Linux 外观一致性承诺 |
| 共享编排核心 | 状态机、配置契约、更新清单、恢复流程；不直接引用 Windows 专属 API | 为未知平台写空壳业务实现 |
| 平台适配 | 集中实现 Windows 进程/目录/凭据/托盘/打开浏览器/文件替换 | 现在实现其他系统密钥库、签名或通知适配 |
| 发行组件 | 清单明确 OS/架构，通用代码不写死盘符、反斜杠、`.exe` 或 Shell 命令 | 宣称同一个 Windows ZIP 可在其他平台运行 |
| 验证 | Windows x64 成品测试、共享核心单元测试及既有 Docker 回归 | 三套桌面系统同时测试与发布 |

以后有明确需求再新增平台适配、对应 Python/PG/浏览器包、系统依赖核验及签名/更新流程。Windows 专属能力允许未来替换或合理降级，不追求所有平台完全一致。跨系统数据迁移仍走已验证备份恢复，不能直接共用或随意复制正在写入的 PGDATA。

不从参考截图推断其内部框架；不以“模仿外观”为理由引入 Electron 或更改后端。未经用户确认不得新增构建/运行依赖。

## 6. 启动、运行和退出状态机

### 6.1 启动顺序

| 阶段 | 行为与通过标准 | 失败处理 |
| --- | --- | --- |
| 0. 窗口与实例锁 | 先显示本地 UI；按规范化数据目录识别唯一实例 | 重复启动唤起已有实例；不得启动第二套数据库 |
| 1. 预检 | 校验组件组合、可写目录、可用空间、端口、遗留维护记录 | 明确错误；缺组件提示修复发行包，不执行 pip |
| 2. 首次初始化 | 仅明确为空的新集群目录允许初始化；初始化标记可恢复 | 非空、损坏或半初始化目录进入诊断，不自动重建 |
| 3. 数据库就绪 | 启动指定 PG，确认自身集群及真实 SQL 连接可用 | 有界等待；超时先复核后台真实状态，再提供重试 |
| 4. 数据版本 | 独占迁移锁，检查 schema；需升级先验证备份 | 不兼容/迁移失败保持维护状态，禁止启动任务 |
| 5. 后端就绪 | 启动指定解释器；验证实例身份、版本、DB 与 schema | 报告真实阶段，避免把占端口的其他服务当成自己 |
| 6. 开放界面 | 成功后打开本机 URL；首次引导创建管理员及业务参数 | 打开浏览器失败不等于后端失败，提供复制地址 |

后台线程/异步任务执行 I/O，UI 不阻塞。普通启动与升级验证使用相同身份检查，但升级验证强制调度暂停；只有验证提交后才能按用户设置恢复业务。

就绪不能仅使用现有 `/health`；新增受保护的内部状态或 IPC，返回发行版本、实例随机标识、数据版本及关键服务状态，公共健康响应不暴露敏感信息。本机端口也不是免认证理由。

### 6.2 超时与取消

- 展示真实阶段和已耗时，如“正在启动数据库 · 第 3/6 步 · 已等待 8 秒”。下载可显示字节百分比，初始化/迁移只显示可测量进度。
- 每阶段设可配置超时和有上限重试策略；具体数值在 P0/P1 实测后确定，不伪造固定启动时长。
- 控制工具返回超时不等于服务器已停止；再次启动前查真实进程及集群状态，避免并发启动。[PG 控制工具说明](https://www.postgresql.org/docs/current/app-pg-ctl.html)
- 普通预检/下载可取消；写入中的初始化、迁移、版本提交等关键段仅允许等待安全点。取消后明确还在运行的组件。

### 6.3 退出、崩溃与恢复

- 只管理自身实例：持久记录路径、PID、进程启动时间、实例/集群标识并在操作前复核；PID 单独不足以证明归属。
- 正常退出：停止接收新任务 → 等待/按业务规则取消在途任务 → 关闭工作进程及连接池 → 停后端 → 受控停止 PG → 验证退出。
- 用户已接受退出等待超时的默认处理：保持服务运行，显示“继续等待、取消退出、确认强制停止”；不自动强杀、不隐藏退出窗口。等待阈值由实测确定。用户手动停止任务、应用退出、维护停机和异常恢复必须区分原因，不能直接复用会发送“用户手动停止”通知的现有流程；具体通知行为按既有业务规则核对，不在启动器适配中擅自改变。
- PG 使用受控停机；强制断开事务须说明影响，禁止把 immediate 或进程强杀当成默认停止方式。
- Launcher 崩溃后重开先做归属核验，允许重新接管可验证的自身实例，未知进程不接管不终止。不能通过删除 `postmaster.pid` 作为通用“修复”。
- Windows 关机/断电不能承诺永不丢失在途工作；必须测试重启恢复。业务幂等与事务承担一致性，不由启动动画替代。

## 7. PostgreSQL 初始化、安全和备份

### 7.1 首次使用

- 随包固定已验证 PG 主版本及补丁版，首次运行使用明确路径初始化新集群，指定 UTF-8 并验证 locale 在目标 Windows 上可用。
- 默认仅监听本机，使用密码认证；每份新实例生成独立随机凭据，不使用 trust 或共享默认密码。
- 初始化/迁移权限与常规应用权限分开，常规后端不以数据库超级用户运行。端口冲突提示并选择可用端口，既有实例端口变化需先确认其停止且不影响连接配置。
- 不默认创建全局服务、修改系统 PATH、打开防火墙。外部数据库仍由既有部署方式管理。
- 首次设置管理员密码，通过受保护的一次性引导通道完成；引导完成后关闭该通道，业务 API 在完成前不得无认证开放。
- 程序密钥、平台登录态及数据库密码不显示在 UI、命令日志、诊断包或可公开命令行中。按用户委托采用安全优先方案：本机保存凭据使用当前系统用户保护机制（具体实现 P0 验证）；换电脑/系统用户默认重新授权，不承诺复制后凭据仍直接可用。已有加密业务数据必须有单独的受密码保护密钥备份/恢复方案，不能以“重新登录”代替数据解密恢复；在恢复演练通过前不宣传跨机器完整迁移。此规则不阻止普通非敏感数据便携。

### 7.2 应用数据迁移

必须建立 schema 版本表、迁移编号、顺序、锁、结果记录和兼容范围，具体迁移工具待确认。`create_all` 不是升级已有表结构的完整迁移体系。非事务性迁移需有单独恢复设计，不能盲目重复运行。

旧源码/JSON 用户导入需：选择准确目录 → 只读预览 → 确认归属账户和排除项 → 备份 → 导入 → 对账数量与关键字段 → 留下结果报告。保留原目录，不自动删除。已有工具不覆盖所有私有 API/通知配置、会话、审计日志；不得把“迁移完成”表达为全部文件已搬迁。

### 7.3 备份与恢复

- 区分“配置备份”“数据库备份”“完整业务备份”，显示包含项、缺失项、版本、时间及大小。
- 数据库优先使用匹配工具的逻辑备份；应用角色等集群级对象须明确重建或纳入受保护备份，不假设单库 dump 包含所有对象。[PG 逻辑备份说明](https://www.postgresql.org/docs/current/backup-dump.html)
- 数据库与文件资产的组合备份需暂停应用写入取得一致性边界；备份包括解密所需密钥的安全恢复方案。禁止边写数据库边普通复制 PGDATA，并把它称作可靠备份。
- 备份校验不仅检查文件存在：需有校验值、可读取检查和定期恢复演练。恢复到隔离位置验证，用户确认后切换，不直接覆盖唯一原始数据。
- 备份恢复可能丢失备份后新增数据，必须预览并确认；诊断包不得替代备份。

## 8. 增量更新与回退

### 8.1 分组件策略

| 变更 | 下载/更新组件 |
| --- | --- |
| 页面与业务修复 | app |
| Python 或依赖变化 | runtime，必要时 app |
| Playwright 变化 | runtime 及其明确匹配的 browsers |
| Launcher 变化 | launcher / 稳定入口，使用独立更新器替换 |
| PG 补丁变化 | postgres，按已验证同主版本流程停机更新 |
| PG 主版本变化 | 独立升级项目，不走普通静默更新 |

Playwright 与浏览器必须匹配，不能无限沿用旧浏览器；组件未变化可复用，但必须校验兼容与完整性。[Playwright 浏览器说明](https://playwright.dev/python/docs/browsers)

首版不承诺包体和增量大小；先实际构建测量再写用户文案。日常 app 更新不重复下载大型运行环境。

### 8.2 发行清单契约

建议清单至少包含：清单格式版本、发行 ID、通道、发布时间、目标系统/架构、最低启动器版本、app/runtime/browser/PG/launcher 的精确 ID、组件大小与 SHA-256、下载地址、schema 来源范围与目标、迁移 ID、恢复策略、发行说明和签名信息。

- 以可信内置公钥验证清单/制品签名；哈希只解决完整性，不等于来源可信。密钥轮换、清单过期和降级限制在 P2 确定。
- HTTPS 与可信发布源；在线与离线导入执行相同验签、兼容与安全解包流程。
- 拒绝路径穿越、绝对路径、重解析点及解压体积超限；所有目标均位于明确暂存目录，不能写入 `data/`。
- 普通更新不执行下载的任意安装脚本；迁移入口来自被验证的发行内容。
- stable 为默认，测试通道后置并需主动选择；发布源和签名方案未确定前不启用自动在线安装。

### 8.3 事务流程

1. 用户检查更新；展示变化、总下载量、空间峰值、停机与迁移提示。
2. 下载到 `.tmp/updates/<transaction-id>/`，断点数据校验后复用，网络失败不影响当前版本运行。
3. 验签/校验/安全解包到新版本目录；旧版本仍完整保留。
4. 用户确认安装，阻止新任务并排空在途任务；记录可恢复更新事务。
5. 停业务写入，生成并核验所需备份；备份失败不得进入迁移。
6. 锁定迁移与应用数据；按签名清单迁移。旧应用此后不能自行重启访问不兼容数据。
7. 以维护模式启动新后端，验证身份、数据库及 schema，禁止真实业务副作用。
8. 验证通过后在同卷以可恢复方式提交 `current.json`，提交前后留事务记录，再允许业务按设置恢复。
9. 失败进入恢复状态；只有数据兼容时才直接回到旧程序。需恢复数据时先提示影响并获得确认；不可逆迁移没有验证恢复方案则禁止发布。
10. 下次启动识别断电遗留阶段，不因看到新目录就认定更新成功。旧版本和共享组件按引用与保留策略清理，不影响当前运行版本。

Launcher 自更新由独立进程在 UI 退出后执行；稳定入口损坏时需有已签名完整包的修复路径。早期可通过完整 ZIP 在独立程序目录恢复，但不得教用户随意覆盖混合新旧文件或覆盖数据。

PG 主版本升级需要专门的 dump/restore 或经验证的 pg_upgrade 流程；不允许把引擎二进制覆盖等同于数据目录升级。[PG 升级说明](https://www.postgresql.org/docs/current/upgrading.html)

## 9. 诊断、日志和磁盘卫生

- 所有外部调用与 I/O 记录上下文和错误；UI 给出可理解说明与错误码，不吞异常，也不只弹“未知错误”。原因：有上下文的错误信息才能帮助用户定位故障并安全恢复。
- 诊断包默认只含版本、脱敏配置摘要、近期组件日志和错误信息；排除完整 `.env`、连接串密码、Cookie、令牌、业务结果、数据库和用户输入。导出前可预览，不自动上传。原因：诊断目的不需要泄露凭据、个人信息或业务数据。
- 遵循 REPOSITORY_HYGIENE.md：开发临时文件统一 `.tmp/<用途>/<任务标识>/`；通用任务 2 GiB 预算仅计该任务新增的专属可重建临时产物，共享依赖缓存和登记批准留存的验收夹具另账；仍须盘点并报告 `.tmp` 全部实际占用，预算超额本身不授权删除。原因：预算限制新增任务成本，同时避免共享资产与验收证据造成误删压力。
- 2026-09-12 用户明确授权便携 Launcher 自动落地任务不受单任务 512 MiB 与 `.tmp` 2 GiB 容量上限约束；该例外仅覆盖容量，不覆盖低于 10 GiB 或 5% 时暂停新增重型产物、数据保护、在用文件保护和期限复核。原因：该项目需要生成大型发行与验收制品，低磁盘及数据安全边界仍需保留。
- 发行更新仍须计算下载、解压、新旧版本与备份峰值；例外授权范围外的任务超过预算须明确提示并取得授权，所有情况都不得为满足预算自动删除用户数据。原因：峰值盘点让空间影响可见，容量管理不能成为删除用户数据的理由。
- 轻量失败诊断最多保留 7 天、每用途最近 3 次；带业务状态的失败验收夹具到期只触发复核，不按此期限自动删除。原因：这类夹具可能保留唯一可复现状态。
- 日志采用大小轮转；过期日志仅由显式清理入口按传入期限处理（默认 7 天）。日志导出包目标规则是在执行自动轮替前明确告知用户将删除的旧包并取得确认；确认后最多保留最近 5 份且删除超过 7 天的 ZIP，在用或无法安全检查的文件跳过。当前实现仍在新包成功导出后自动删除超出数量或期限的旧 ZIP，尚无导出前明确告知和确认，属于待实现差异；完成实现和测试前不得称其符合目标规则。原因：删除旧包会移除历史文件，用户须在轮替发生前了解并确认范围。
- 备份、数据库、登录态、原始结果不是缓存；保留数量不能成为未经确认删除它们的理由。原因：这些内容可能是唯一业务副本或恢复凭据。
- 任何清理只针对已验证、无引用、非在用的准确路径，检查目录边界、junction/符号链接、并发占用与权限错误；先预览，失败不强删。原因：路径及占用核验可避免范围外删除或破坏正在写入的数据。

## 10. 实施里程碑和交付物

- 统计功能实施前再确认：事件保留期与容量。未实现统计前不要求用户预先决定精确天数。
