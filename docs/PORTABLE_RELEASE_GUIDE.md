## 当前发行状态

截至 2026-09-24，2026-09-23 的 r2 ZIP 仅是旧源码历史验收包，不代表当前源码，也不是发行包。Chromium/ONNX notice 原文和 104 项 collector/scanner fail-closed 定向检查已通过，但尚未用当前冻结源码重建、扫描最终 ZIP。r1 有真实 Host→PostgreSQL 加密备份/恢复 PASS；r2 旧包通过两次 Host→PG 空实例启动/停止周期，两者都不等于当前最终源码包通过。Docker 已启动并完成隔离 Compose app+PostgreSQL health/login 本机烟测，原有容器卷保留；该烟测早于当前源码改动冻结，需在最终冻结后重跑。无开发工具干净 Windows、原生窗口/DPI 和 Explorer 托盘验收仍未完成。恢复 UI 与托盘生命周期已有实现及 Headless Smoke 证据，但尚未通过原生 UI 验收。验收状态以[便携版验收状态](PORTABLE_ACCEPTANCE_STATUS.md)为准。

## 下载、校验与解压

正式发布时，请只从上表填写的项目发行页下载完整 ZIP。下载结束后，在 PowerShell 中用实际文件路径检查 SHA-256，并与同一发行页公布的值逐字比对：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '下载目录中的完整包.zip'
```

只有哈希完全一致才继续。解压后保留完整目录结构；不要只复制 Launcher EXE，也不要把程序文件解压覆盖到旧版本目录。若发行包附带 manifest，按该版本提供的校验步骤核验文件集合与哈希。清单能发现缺失或意外改动，不能替代可信下载来源或代码签名。

将完整包解压到当前 Windows 用户有读写权限的目录。首次试用请使用新的空目录，避免覆盖源码、既有便携目录或任何业务数据。不要以管理员身份运行。PostgreSQL 数据目录需要在服务运行期间保持可用且稳定；云同步目录、网络共享或可能被意外拔出的介质可能造成文件冲突、I/O 中断或数据库损坏。若使用可移动介质，应确保运行期间不会断开，并有经过验证的独立备份。

## 首次启动与账号设置

以下流程仅适用于通过正式放行的发行包；当前本地 r2 验收包不满足这一条件。

1. 确认 ZIP 已完整解压、manifest 检查通过，目标目录可读写，并且默认 PostgreSQL/Web 端口没有被其他应用占用。端口冲突时应停止并处理冲突，不要终止不明进程或尝试接管已有 PostgreSQL。
2. 双击发行说明指定的 Launcher 主程序。启动器先验证包并显示组件状态；用户点击“一键启动”后才会在数据根中初始化首次便携实例。若初始化中断或目录出现损坏/未知状态，停止操作并保留错误信息，不删除标记、密钥或数据库文件，也不要尝试清空重建。
3. 使用 Launcher 的启动操作启动受管 PostgreSQL 和 Web 服务。只有 Launcher 显示业务 Web 已就绪后再打开本机页面。若页面无法打开，按组件状态定位问题；不要把所有故障都当作数据库故障。
4. 在首次设置页按提示创建唯一管理员账号。便携版不应使用公开的共享默认密码。妥善保管用户自行设置的密码；不要把一次性设置口令、密码或 API 密钥贴入 Issue、日志或诊断附件。
5. 完成账号登录后，先核对系统配置和所需功能，再自行决定是否添加闲鱼账号、监控任务、通知渠道或 AI API 密钥。健康/就绪检查不代表真实抓取或 AI 调用成功；手动 API 测试可能产生费用，应只在明确需要时触发。

便携版默认仅面向本机访问。它不会自动配置公网/LAN 访问、Windows 服务、开机自启或防火墙规则。离线安装启动不代表闲鱼抓取、通知和云端 AI 能力可以离线使用。

## 程序目录与业务数据

便携版把程序组件与用户数据分开管理。程序目录容纳 Launcher 和锁定的运行组件；便携数据根保存 PostgreSQL 集群及业务文件。实际位置应以该发行版 Launcher 显示和对应发布说明为准。切勿把程序目录误认为备份，也不要手工改写实例标记、活动实例指针、配置或 DPAPI 保护文件。

移动或升级时先通过 Launcher 正常停止 Web/Python 工作进程和 PostgreSQL，并确认均已停止。不要在服务运行时复制 PGDATA，不要把两个程序目录配置为同时写入同一数据根。数据文件和本机进程身份不是可随意复制的普通程序文件；DPAPI 凭据绑定 Windows 用户及实例上下文，换 Windows 用户或电脑后不能假定原凭据可解密。

## 备份与恢复

当前源码已接入停写后创建加密业务备份的 Launcher 入口，并有隔离恢复编排、确认状态机和恢复 UI；UI 目前只有 Headless Smoke 证据。r1 包的真实 Host→PG 备份/恢复 E2E 已通过，但没有在当前最终源码 ZIP 上复验，因此当前仍没有面向普通用户、可按本节操作的完整备份/恢复发布流程。不要把 ZIP、诊断导出或直接复制 PGDATA 称为可验证的完整备份，也不要将它们作为唯一数据副本。

未来正式开放该能力后，应通过 Launcher 选择数据根之外的新备份文件、设置并妥善保存备份口令；备份会包含数据库、受支持的业务文件和恢复密钥，并明确排除日志、缓存、PGDATA 和本机进程凭据。恢复必须创建独立的新实例，先验证备份来源和口令，核对表行数、文件及密钥，再由用户确认切换。恢复前的旧实例应保留，恢复完成后也不会自动启动任务。PG 逻辑备份包含可执行 SQL，只能恢复可信来源的备份。

在正式发布说明明确宣布该版本的恢复 UI 和实机演练通过前，遇到迁移、恢复或数据损坏需求，请保留原目录并提交脱敏诊断；不要自行删除旧实例或执行内部 helper 命令。

## 完整包手工升级

P1 不提供已验收的增量更新器或安全升级事务。正式说明允许手工升级时，按该版本专属步骤操作；最低限度应先正常停止服务、创建并验证独立备份，然后将新完整 ZIP 解压到一个新的程序目录。只有对应版本的恢复/迁移流程已正式放行、并确认数据切换步骤与备份可用后，才能按说明将既有数据接入新版本。

当前阶段请不要覆盖旧程序目录、覆盖或复制运行中的数据目录，也不要删除旧目录来腾空间。若新版本的受保护恢复流程还未放行，只能在全新独立目录中做空数据试用；保留旧程序和旧数据原样。手工覆盖文件不是升级方案。

## 退出与诊断

关闭 Launcher 时按界面提供的后台运行、安全退出或取消选项选择；安全退出应等待受管 Web/工作进程排空并按归属核验停止服务。若进程状态未知或等待超时，不要通过任务管理器盲目终止 PostgreSQL，也不要删除运行标记或锁文件。托盘生命周期已有 Headless Smoke 证据，但 Explorer 原生托盘操作尚未验收；Headless 结果不代表原生托盘已经放行。

诊断导出设计为有限字段、用户预览后另存的新文件，不应包含配置值、Cookie、密钥或业务数据。分享前仍请自行检查导出内容并移除个人信息。不要公开上传数据库、备份包、完整日志或真实账号信息。

## 已知限制

- Windows x64 是首期目标；最低 Windows 版本尚未由干净系统验证确定。
- Chromium/ONNX notice 原文和 104 项 collector/scanner fail-closed 定向检查已通过；当前源码的最终 ZIP 尚未重建和扫描。
- r1 真实 Host→PG 备份/恢复 E2E 已通过；当前最终源码 ZIP 的备份/恢复 E2E 和恢复后 Web/worker 衔接尚未验收。恢复 UI 已实现，但只通过 Headless Smoke。
- Docker 隔离 Compose app+PostgreSQL health/login 本机烟测已通过且保留原有容器卷；由于烟测早于当前源码变更冻结，最终冻结后仍需复跑。
- 无开发工具干净 Windows、原生窗口与多档 DPI/键盘可用性尚未验收。
- 关闭选择和托盘生命周期已有 Headless Smoke；Explorer 原生托盘、多档 DPI、真实故障/断电恢复和完整数据迁移仍未验收。
- P1 不包含安全离线更新器、在线更新、schema 迁移事务、旧 JSON 自动导入或安装向导。
- 便携版启动本地服务不改变任务抓取频率、账号隔离、AI 调用或通知策略；网络平台的可用性和使用规则由用户自行确认。

便携版与 Docker 是两条并行路线，共用业务后端。便携版面向 Windows x64 本机目录；Docker 用户继续使用项目现有 Docker 文档、Compose 文件、环境变量和卷挂载说明。不要让 Docker 直接使用便携实例正在写入的 PGDATA，也不要声称可跨部署路线复制 PGDATA 完成迁移。
